# net-speed-meter

Скрипт замеряет скорость интернета со своего компьютера: делает 10 последовательных запросов к тяжелому файлу, дожидается полного ответа, считает среднее время запроса, объем скачанных данных и печатает скорость в МБ/с.

Только стандартная библиотека Python, зависимостей нет.

## Требования

Python 3.9+

## Запуск

```bash
git clone https://github.com/Baho73/net-speed-meter.git
cd net-speed-meter
python speedmeter.py https://proof.ovh.net/files/10Mb.dat
```

Подойдет любой тяжелый файл: большая картинка, архив, тестовый файл провайдера. Файл на 5-10 МБ дает стабильный результат: на мелком файле замер съедают DNS, TLS-рукопожатие и задержка сервера.

Параметры:

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `url` | обязательный | адрес тяжелого файла (большая картинка, архив) |
| `-n`, `--requests` | 10 | сколько запросов сделать |
| `-t`, `--timeout` | 30 | таймаут одного запроса, секунд |
| `--no-cache-bust` | выключен | не добавлять к адресу параметр против кэша |

Пример вывода:

```
# 1:  0.412 с,    3.40 МБ,    8.25 МБ/с
...
#10:  0.398 с,    3.40 МБ,    8.54 МБ/с
--------------------------------------------
Успешных запросов: 10 из 10
Среднее время запроса: 0.405 с
Скачано всего: 34.00 МБ
Средняя скорость: 8.40 МБ/с (67.2 Мбит/с)
```

## Как считается

- Запросы идут строго последовательно, каждый ждет полного скачивания тела ответа.
- Время запроса: от отправки до получения последнего байта.
- Средняя скорость: весь скачанный объем, деленный на суммарное время запросов. Так медленный запрос честно тянет среднее вниз.
- К адресу добавляется уникальный параметр `_nocache`, чтобы прокси и CDN не отдавали файл из кэша.
- Упавший запрос печатается как ошибка, среднее считается по успешным.

## Решения и на что обратил внимание

- **МБ/с или Мбит/с.** В задании «мб/с», а в быту скорость интернета меряют в мегабитах. Печатаю оба значения, чтобы результат не читали в 8 раз неверно. МБ здесь двоичный, 1024 x 1024 байт.
- **Кэш.** Без параметра `_nocache` второй и следующие запросы может отдать кэш прокси или CDN, и скорость получится завышенной. При проверке нашел обратную сторону: Wikimedia на такие запросы отвечает `429 Too many requests`. Для таких серверов есть флаг `--no-cache-bust`.
- **Честное среднее.** Считаю весь объем, деленный на суммарное время, а не среднее из десяти скоростей. Среднее скоростей завышает результат: один быстрый запрос весит столько же, сколько один медленный, хотя шел в разы меньше времени.
- **Потоковое чтение.** Тело ответа читается кусками по 64 КБ, файл не держится в памяти целиком. Можно мерить на гигабайтном файле.
- **Отказы.** У каждого запроса таймаут. Упавший запрос не роняет замер, он печатается, а итог считается по успешным. Если не прошел ни один, код возврата 1: так скрипт удобно звать из cron или CI.
- **Без зависимостей.** Только стандартная библиотека: скрипт запускается на любой машине с Python без `pip install`.

Что добавил бы под боевую задачу: вывод в JSON для графиков в мониторинге, отдельный замер задержки (время до первого байта) и параллельные запросы, чтобы упираться в канал, а не в один TCP-поток.

Код написан с помощью Claude Code и вычитан вручную: расчеты проверены тестом, поведение с кэшем и 429 проверено на живых серверах.
